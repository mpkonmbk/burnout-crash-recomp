# Burnout CRASH! (58410B5D) — ReXGlue recompilation

Static recompilation of the XBLA build (title update 3) with ReXGlue SDK 0.10.0.24-dev (nightly 2026-10-02).

## Layout

| Path | What |
|---|---|
| `game/` | your extracted package — the game data root (`game:`); not in git |
| `third_party/rexglue-sdk/win-amd64/` | prebuilt SDK; not in git |
| `burnoutcrash_manifest.toml` | entrypoint `DEFAULT.XEX` + DLL module `CRASH.DLL.XEX` (`game:\DLL\CRASH.DLL.XEX`) |
| `config/default.toml`, `config/crash_dll.toml` | codegen overrides (see below) |
| `src/` | app, hooks and native overrides |
| `tools/` | STFS package verifier/extractor |
| `generated/` | codegen output (regenerated by the build); only `rexglue.cmake` is in git |

## Build and run

See [README.md](README.md). `CMakeLists.txt` checks the SHA-256 of both executables at configure time;
codegen re-runs automatically when `config/*.toml` changes (`.\build.ps1 -Codegen` forces it). Access
violations are written with a symbolized stack to `crash_trace.txt` next to the exe
(`src/crash_trace.cpp`).

## Fixes on top of plain codegen

- **default.xex function entries** (`config/default.toml`): thunks reached only by tail calls,
  CRT static initializers (`__xc_a` table at 0x82950000), vtable methods/adjustor thunks, vcall
  thunks used as pointer-to-member callbacks, and entries after calls to no-return functions.
  Found by scanning data and `lis`/`addi` pairs for code pointers that are neither a registered
  function nor an in-function label.
- **CRASH.DLL.XEX switch tables** (`config/crash_dll.toml`): EASharp's AOT compiler builds jump-table
  addresses with `li`+`addis`, which ReXGlue doesn't detect (it emitted indirect calls instead).
  140 tables declared explicitly; where only `index*4` survives each label is repeated 4x, and where
  the `lwzx` overwrote the index, `SwitchIndexFromTarget` (`src/switch_hooks.cpp`) recovers it.
- **EA callstack walker** `sub_82651230` (`src/guest_overrides.cpp`): replaced with a bounds-checked
  native version — under ReXGlue the outermost frame's back chain is the stack top, so the original
  read past the thread stack.
- **`XUserFindUsers`** `sub_82842F48` (`src/guest_overrides.cpp`, crash on PLAY): the runtime doesn't
  handle XLIVEBASE message 0x58017, the game's wrapper bails without completing its XOVERLAPPED,
  and the caller reads the zeroed overlapped as success and walks garbage. Now completes with
  `ERROR_FUNCTION_FAILED` / `X_ONLINE_E_LOGON_NOT_LOGGED_ON`, as an offline console would.
  Other XLIVEBASE messages the game uses that the runtime lacks (0x5800C/D, 0x58019, 0x5801E,
  0x58044, 0x58052) belong to unused library functions; 0x5800E is sync and fails harmlessly.
- **Full game instead of trial** (`src/burnoutcrash_app.h`): `license_mask` defaults to 1 (the game
  tests bit 0 of `XamContentGetLicenseMask`); `--license_mask=0` brings the trial back.

Known gaps: SEH `__except`/C++ catch funclets (referenced from the scope tables at 0x82154000–
0x82155C00, and 3 in the DLL) are not registered, so a guest exception that reaches one will
fail. `XamXStudioRequest` is an SDK stub (called every frame; harmless).
